# Future curriculum and architecture extension

Planning only. No OS, DBMS, networking, aptitude, reasoning or verbal curriculum is implemented by this change. The current stop point is the reviewed UI + engineering reasoning/codebase release.

## Possible later tracks

| Track | Candidate content | Distinct assessment boundary | Prerequisite before build |
|---|---|---|---|
| CS fundamentals | OS, DBMS, networks, OOP, architecture, compilers, discrete math, security, cloud/distributed systems, software engineering, languages, concurrency/memory | Authored conceptual/scenario evidence, bounded exercises where appropriate; no generic keyword score | Reviewed learning objectives, misconception corpus, subject reviewer and original/licensed content |
| Quantitative aptitude | Percentages, ratios, profit/loss, work/time, speed/distance, probability, combinatorics, numbers, algebra, geometry, data interpretation | Exact numeric/symbolic verification with stated tolerances and explanation evidence | Independent solution/oracle review and accessibility for figures/tables |
| Logical reasoning | Seating, puzzles, syllogisms, deductions, series, coding, data sufficiency, analytical reasoning | Constraint satisfaction and proof/counterexample, not phrase matching | Verified answer sets, alternative-valid answers and ambiguity review |
| Verbal ability | Reading, grammar, vocabulary, correction, ordering, sentence completion, professional communication | Evidence-supported language feedback; separate accent/transcription from meaning | Rights-cleared passages, rubric calibration and language accessibility review |

## Extension approach

Retain separate aggregates/evaluators for coding execution, architecture graph checks and repository evidence. A future mode adapter should define versioned authored content, artifact schema, transition logic, objective verifier, interpretive rubric with abstention, export/deletion and review policy. Shared capability authorization, transport, speech, timeline and review UI can compose those adapters without making a diagram a fake code revision or treating a multiple-choice answer as open-ended engineering evidence.

Content identities are stable ID + semantic version + content hash. Active sessions pin content. Numeric answers, choices, passages, prose and diagrams have different validation contracts. Future progress should reference actual completion/assessment events and label unassessed dimensions; a review rating measures a learner's reported recall, not certified mastery.

Before any next track: finish current acceptance evidence, review the integration candidate combining Claude/Codex changes, obtain explicit next-stage authorization, and review privacy/cost/deployment separately. Suggested sequence is one carefully authored fundamentals vertical journey, then evaluate learning results before expanding a full catalog. No calendar estimate or effectiveness guarantee is implied.
